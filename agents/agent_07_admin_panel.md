# Agent 07 — Admin Panel

## 1. Цель

Реализовать веб-интерфейс администратора на FastAPI по [06_admin_panel.md](../06_admin_panel.md): авторизация, CRUD документов, публикация, индексация, фильтры, статус, просмотр audit.

## 2. Контекст

Индексация через `RagService`/ingest (agent_05); модели документов (agent_04).

## 3. Что уже готово

- Каркас приложения (agent_02), сессии БД.

## 4. Что именно нужно сделать

- FastAPI `app` в `admin/app.py`, маршруты CRUD, Jinja2 шаблоны.
- CSRF для форм (или double-submit token).
- Вызов индексации после сохранения при флаге `auto_index_on_publish`.
- Страницы `/status`, `/audit` (последние записи).
- Секрет сессии из `.env`.

## 5. Какие файлы можно менять

- `src/medvopros/admin/**`, `src/run_admin.py`, при необходимости общий `health` роутер.

## 6. Какие файлы нельзя менять

- Не дублировать SQL чанкинга в роутах — только вызов сервисов RAG.

## 7. Зависимости

- **После** agent_04; **после или вместе** с agent_05 для кнопки индексации.

## 8. Критерии завершения

- Пункты G1–G3 и B1 из [12_acceptance_checklist.md](../12_acceptance_checklist.md) выполнимы.
- Без авторизации CRUD недоступен.

## 9. Формат отчёта агента

- **Что сделано**
- **Какие файлы изменены**
- **Что проверить вручную** (HTTPS, пароль админа)
- **Риски** (брутфорс логина — rate limit этап 2)
- **Проверка успешности этапа** — обязательно **последним разделом** отчёта (`agents/report_agent_07_admin_panel.md`): заполнить п. 10; URL и скриншоты **без** сессионных cookie в репозитории.

## 10. Шаблон финального раздела отчёта: «Проверка успешности этапа»

### Проверка успешности этапа (Agent 07 — Admin Panel)

| Шаг | Действие | Ожидание | Результат |
|-----|----------|----------|-----------|
| 1 | `python src/run_admin.py`, открыть базовый URL | Страница логина или редирект на него | OK/FAIL |
| 2 | Неверный пароль | Отказ, без утечки stack trace наружу | OK/FAIL |
| 3 | Верный пароль | Доступ к списку документов | OK/FAIL |
| 4 | Создание документа (title, slug, body) | Запись в БД, редирект/список обновлён | OK/FAIL |
| 5 | Редактирование, смена статуса draft/published | Поля и статус сохраняются | OK/FAIL |
| 6 | Кнопка/действие индексации (если уже связано с RAG) | Успех или сообщение об ошибке в UI; запись в `audit_log` при наличии | OK/FAIL |
| 7 | Доступ к CRUD без сессии | 401/403/редирект на логин | OK/FAIL |
| 8 | Сверка с [12_acceptance_checklist.md](../12_acceptance_checklist.md), блок **G**, **B1** | Отмечено | OK/FAIL |

Этап **успешен**, если 3–5 и 7 — OK.

В продакшене проверять **HTTPS** отдельно; в отчёте указать, тестировали ли по HTTP локально.
