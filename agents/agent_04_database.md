# Agent 04 — Database

## 1. Цель

Реализовать модели SQLAlchemy, миграции Alembic (включая pgvector), репозитории согласно [03_database_design.md](../03_database_design.md).

## 2. Контекст

Схема таблиц, индексы и векторное поле описаны в документе БД; биллинг и сообщения используются в [07_billing_and_limits.md](../07_billing_and_limits.md) и [05_bot_logic.md](../05_bot_logic.md).

## 3. Что уже готово

- Каркас сессии БД от agent_02 (или параллельная интеграция).

## 4. Что именно нужно сделать

- Модели: `users`, `messages`, `documents`, `document_chunks` с типом `Vector`, остальные сущности MVP.
- Миграция: `CREATE EXTENSION vector`; размерность вектора согласовать с [09_config_and_env.md](../09_config_and_env.md).
- Репозитории: `UserRepository`, `MessageRepository`, `DocumentRepository`, `ChunkRepository`, `BillingRepository`, `AuditRepository` — минимальные методы для последующих агентов.
- Индексы: перечисленные в дизайне; векторный индекс с разумными параметрами для пустой БД (комментарий в миграции о пересоздании после наполнения).

## 5. Какие файлы можно менять

- `src/medvopros/db/**`, `src/medvopros/repositories/**`, `alembic/**`.

## 6. Какие файлы нельзя менять

- Бизнес-логику списания в репозиториях без согласования — только CRUD и запросы; правила в `billing_service`.

## 7. Зависимости

- **После** agent_02; блокирует agent_05, agent_07, agent_08.

## 8. Критерии завершения

- `alembic upgrade head` применяется на чистой БД без ошибок.
- Репозитории покрыты минимальными тестами или ручной проверкой CRUD.

## 9. Формат отчёта агента

- **Что сделано**
- **Какие файлы изменены**
- **Что проверить вручную** (версия PostgreSQL, pgvector)
- **Риски** (смена размерности эмбеддингов)
- **Проверка успешности этапа** — обязательно **последним разделом** отчёта (`agents/report_agent_04_database.md`): заполнить п. 10; приложить вывод `alembic current` и при необходимости `\dx` / список таблиц **без** паролей в логах.

## 10. Шаблон финального раздела отчёта: «Проверка успешности этапа»

### Проверка успешности этапа (Agent 04 — Database)

| Шаг | Действие | Ожидание | Результат |
|-----|----------|----------|-----------|
| 1 | Чистая БД (или тестовая), корректный `DATABASE_URL` | Подключение с хоста разработки | OK/FAIL |
| 2 | `alembic upgrade head` из корня проекта (или задокументированный CWD) | Миграции без ошибок | OK/FAIL |
| 3 | `alembic current` | Хэш ревизии совпадает с head | OK/FAIL |
| 4 | В `psql` или GUI: `SELECT extname FROM pg_extension WHERE extname = 'vector';` | Строка `vector` присутствует | OK/FAIL |
| 5 | Список таблиц содержит сущности из [03_database_design.md](../03_database_design.md) (users, messages, documents, document_chunks, …) | Все таблицы MVP созданы | OK/FAIL |
| 6 | Колонка эмбеддинга: тип `vector` и размерность согласована с `config.ini` (`embedding_dimensions`) | Соответствие | OK/FAIL |
| 7 | Запуск тестов: `pytest` (или целевой путь `tests/…`) для репозиториев | Зелёные тесты или N/A с объяснением | OK/FAIL |
| 8 | Минимальный CRUD через репозиторий или скрипт | Создание/чтение записи без ошибки | OK/FAIL |

Этап **успешен**, если шаги 2–6 — OK.

**Не** коммитить вывод с DSN, содержащим пароль.
