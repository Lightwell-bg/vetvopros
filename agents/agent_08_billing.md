# Agent 08 — Billing

## 1. Цель

Реализовать лимиты, модели тарифов, списание ответов, заготовку платёжного провайдера и активацию пакетов/подписок согласно [07_billing_and_limits.md](../07_billing_and_limits.md).

## 2. Контекст

Таблицы и поля: [03_database_design.md](../03_database_design.md); события аудита и UX бота: [05_bot_logic.md](../05_bot_logic.md).

## 3. Что уже готово

- Репозитории и модели (agent_04).

## 4. Что именно нужно сделать

- `BillingService`: `check_and_consume_answer_credit(user_id, source_type) -> bool`, приоритет подписка → пакет → бесплатный лимит.
- Инициализация `user_balances` при первом визите пользователя.
- Заготовка `billing/provider_stub.py`: создание «платежа», ручное подтверждение для демо или фиктивный webhook.
- Запись `audit_log` на списание и начисление.
- Конфигурируемые числа из `config.ini` (`free_answers_per_user`, и т.д.).

## 5. Какие файлы можно менять

- `src/medvopros/billing/**`, `src/medvopros/services/billing_service.py`, репозитории при необходимости расширения API.

## 6. Какие файлы нельзя менять

- Telegram handlers — только вызов сервиса.

## 7. Зависимости

- **После** agent_04; до финальной интеграции agent_03.

## 8. Критерии завершения

- Пункты D1–D4 чеклиста [12_acceptance_checklist.md](../12_acceptance_checklist.md) выполнимы.
- Идемпотентность начисления при повторном «подтверждении» stub-платежа.

## 9. Формат отчёта агента

- **Что сделано**
- **Какие файлы изменены**
- **Что проверить вручную** (SQL-снимки баланса)
- **Риски** (гонки при concurrent запросах — транзакции)
- **Проверка успешности этапа** — обязательно **последним разделом** отчёта (`agents/report_agent_08_billing.md`): заполнить п. 10; в отчёте — агрегированные цифры по пользователю, **без** персональных идентификаторов или с псевдонимом `user_id`.

## 10. Шаблон финального раздела отчёта: «Проверка успешности этапа»

### Проверка успешности этапа (Agent 08 — Billing)

| Шаг | Действие | Ожидание | Результат |
|-----|----------|----------|-----------|
| 1 | Новый пользователь: первое обращение к биллингу | Создаётся запись баланса/начальное состояние по ТЗ | OK/FAIL |
| 2 | Исчерпание бесплатного лимита (`free_answers_per_user` из конфига) | Следующий «ответ» блокируется; `source` или событие = billing | OK/FAIL |
| 3 | Начисление пакета (stub или SQL) | `pack_credits` увеличивается; ответ снова разрешён | OK/FAIL |
| 4 | Списание за ответ не дублируется при повторе сценария с тем же idempotency-ключом (если реализовано) | Одно списание | OK/FAIL |
| 5 | Подписка активна: приоритет над пакетом/бесплатным (по [07_billing_and_limits.md](../07_billing_and_limits.md)) | Поведение соответствует документу | OK/FAIL |
| 6 | Записи в `audit_log` на списание/начисление | События присутствуют | OK/FAIL |
| 7 | `pytest` по биллингу (если есть) | Зелёные тесты | OK/FAIL/N/A |
| 8 | Сверка с [12_acceptance_checklist.md](../12_acceptance_checklist.md), блок **D** | Отмечено | OK/FAIL |

Этап **успешен**, если 2, 3, 6 — OK и нет расхождения с документом `07`.
