# Agent 09 — Medical Guardrails

## 1. Цель

Реализовать слой медицинских ограничений: правила red flags, загрузка markdown-дисклеймеров, безопасные сценарии интерпретации анализов, единый интерфейс для `AnswerService` и handlers.

## 2. Контекст

Требования: [08_specialists_and_medical_flows.md](../08_specialists_and_medical_flows.md), [00_project_overview.md](../00_project_overview.md).

## 3. Что уже готово

- Модуль `texts/markdown_loader.py` (или его следует создать здесь/в agent_02 — согласовать без дублирования).
- Пути к файлам в `config.ini`.

## 4. Что именно нужно сделать

- `medical/guardrails.py`: функция `evaluate(user_text) -> GuardrailResult` с полями `action` (`allow`, `block`, `escalate`), `response_text` (из шаблонов), `reason_code`.
- Набор ключевых правил/паттернов для MVP red flags (расширяемый список).
- Загрузка текстов из `texts/*.md` по ключам конфигурации.
- Вспомогательные методы для префикса дисклеймера в сценариях анализов.
- Документировать в коде, что слой **не заменяет** юридическую экспертизу текстов.

## 5. Какие файлы можно менять

- `src/medvopros/medical/**`, `src/medvopros/texts/**`, файлы в корневом `texts/` (содержимое markdown), при необходимости примеры в `prompts/`.

## 6. Какие файлы нельзя менять

- Не ослаблять требования ТЗ ради краткости кода; не хранить дисклеймеры только в коде без согласования.

## 7. Зависимости

- Можно начинать после agent_02; **до** полной склейки agent_03 и agent_06.

## 8. Критерии завершения

- Пункты E1–E3 из [12_acceptance_checklist.md](../12_acceptance_checklist.md) выполнимы.
- Unit-тесты на несколько фраз red flag и негативные примеры.

## 9. Формат отчёта агента

- **Что сделано**
- **Какие файлы изменены**
- **Что проверить вручную** (контент markdown с врачом-редактором)
- **Риски** (false positive/negative у ключевых слов)
- **Проверка успешности этапа** — обязательно **последним разделом** отчёта (`agents/report_agent_09_medical_guardrails.md`): заполнить п. 10; тестовые фразы в отчёте — обезличенные.
