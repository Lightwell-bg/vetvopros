# Отчёт Agent 06 — LLM Integration

## Что сделано

- Добавлен **`LlmService`** (`src/medvopros/services/llm_service.py`): OpenAI-compatible **`/v1/chat/completions`**, методы **`complete_with_system`**, **`complete`** (совместимость с протоколом **`LlmClient`**), загрузка промптов с диска по путям из конфига (**`load_main_system_prompt`**, **`load_analysis_*`**, **`load_prompt_at`**).
- **Ретраи** при таймауте и сетевых ошибках **`httpx`**, а также при HTTP **429**, **502**, **503**, **504**; пауза с экспоненциальным backoff от **`retry_backoff_seconds`**; для **429** учитывается заголовок **`Retry-After`**, если он числовой.
- Контролируемая ошибка **`LlmError`** с текстом без ключа API; **`MedAnswerService`** обрабатывает её отдельно от прочих исключений (пользователю — общий текст из **`texts/error_generic.md`**).
- **Логирование:** при **`reduce_log_detail = true`** в **`config.ini`** в лог уходят только модель, latency, длины контента, без превью полного текста промптов и ответа.
- В **`config.ini`** / **`IniLlm`**: **`max_retries`**, **`retry_backoff_seconds`**, **`reduce_log_detail`** (с безопасными значениями по умолчанию при отсутствии ключей в ini через **`get`** в парсере).
- **`OpenAiCompatibleLlm`** оставлен как **алиас** на **`LlmService`** в **`llm_client.py`** для обратной совместимости импортов.
- Юнит-тесты с моками **`httpx`**: **`tests/test_llm_service.py`**.

## Какие файлы изменены / добавлены

- Добавлены: `src/medvopros/services/llm_service.py`, `tests/test_llm_service.py`, `agents/report_agent_06_llm.md`.
- Изменены: `src/medvopros/services/llm_client.py`, `src/medvopros/services/__init__.py`, `src/medvopros/services/answer_service.py`, `src/medvopros/bot/app_factory.py`, `src/medvopros/config/settings.py`, `config.ini`, `README.md`.

## Что проверить вручную

- В **`config.ini`** задать актуальное имя модели в **`[llm] chat_model`** для вашего провайдера.
- Краткий запрос к реальному API с рабочим ключом в **`.env`** (`LLM_API_KEY` или `OPENAI_API_KEY`) и при необходимости **`LLM_BASE_URL`**.
- Временно уменьшить **`request_timeout_seconds`** и убедиться, что бот не падает целиком, а возвращает сценарий ошибки.
- Временно подставить неверный ключ: в логах и ответе пользователю не должно быть строки ключа.

## Риски

- **Стоимость и задержки:** каждый ретрай увеличивает время ответа и может удвоить списания у части провайдеров при повторной отправке (зависит от биллинга API).
- **Логи:** при **`reduce_log_detail = false`** в лог могут попадать чувствительные формулировки из пользовательских сообщений (превью); для production держите **`reduce_log_detail = true`**.
