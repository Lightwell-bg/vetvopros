# Agent 03 — Telegram Bot

## 1. Цель

Реализовать Telegram-бота на **aiogram 3.x** (`Bot`, `Dispatcher`, `Router`): команды, меню, callback-кнопки, сценарии из [05_bot_logic.md](../05_bot_logic.md); handlers остаются тонкими — только вызов сервисного слоя, **без** SQL.

## 2. Контекст

Медицинские ограничения и тексты: [08_specialists_and_medical_flows.md](../08_specialists_and_medical_flows.md), биллинг UX: [07_billing_and_limits.md](../07_billing_and_limits.md).

## 3. Что уже готово

- Каркас backend (agent_02), контракты сервисов — по мере готовности `AnswerService`, `BillingService`, `GuardrailService`.

## 4. Что именно нужно сделать

- **`src/run_bot.py`:** `asyncio.run(main())` — создание `Bot(token)`, `Dispatcher`, подключение роутеров из `handlers/`, `dispatcher.start_polling(...)` (или webhook по флагу конфига на этапе 2).
- Регистрация хендлеров (`@router.message(CommandStart())`, и т.д.): `/start`, `/help`, личный кабинет, сценарии анализов/специалистов при включённых флагах.
- Дисклеймер и запись `disclaimer_accepted_at` через репозиторий пользователя; при старте/остановке процесса бота — массовый сброс согласия (`run_bot.py`).
- После ответа `AnswerService` — inline-меню (ещё вопрос, специалист, анализы, кабинет).
- Релей со специалистом: отдельный роутер, FSM сессии, таблица `specialist_relay_maps`, биллинг сообщений специалисту.
- Вызов `AnswerService.ask(user_id, text) -> AnswerResult` (`text`, `source`, `metadata`); синхронные сервисы/БД — через **`asyncio.to_thread`** или единый helper, **без** блокировки event loop.
- Обработка ошибок и длинных сообщений (обрезка/разбиение по лимитам Telegram).
- Inline-кнопки (`InlineKeyboardMarkup`) для принятия дисклеймера и навигации MVP; фильтры callback `callback_data`.

## 5. Какие файлы можно менять

- `src/medvopros/bot/**`, `src/medvopros/handlers/**`, `src/run_bot.py`, при необходимости тонкие правки `services/*` для контрактов.

## 6. Какие файлы нельзя менять

- Логику RAG/эмбеддингов внутри handlers — запрещено; только вызов сервисов.

## 7. Зависимости

- **После** agent_02 (в проекте зафиксирована зависимость **`aiogram`** в `pyproject.toml`).
- **После или совместно** с agent_04 (пользователь в БД), agent_08 (лимиты), agent_09 (guardrails), agent_06 (LLM через AnswerService).

## 8. Критерии завершения

- Пройдены сценарии C1–C3 из [12_acceptance_checklist.md](../12_acceptance_checklist.md) вручную в Telegram.
- Handlers не содержат прямых SQL-запросов.

## 9. Формат отчёта агента

- **Что сделано**
- **Какие файлы изменены**
- **Что проверить вручную** (токен бота, тестовый пользователь)
- **Риски** (блокировка event loop синхронным SQL; FSM в памяти; лимиты long polling)
- **Проверка успешности этапа** — обязательно **последним разделом** отчёта (`agents/report_agent_03_telegram_bot.md`): заполнить п. 10 с результатами ручных и автоматических проверок; скриншоты опционально, **без** персональных данных других пользователей.
